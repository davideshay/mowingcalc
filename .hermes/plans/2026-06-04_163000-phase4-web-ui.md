# Phase 4: Web UI Plan

## Goal
Build a responsive web UI (desktop-first, adapts to mobile) for configuration, monitoring, and history.

## Design Approach
- **Responsive, not mobile-first** — looks polished on desktop, adapts cleanly to tablet/mobile
- **Tailwind CSS** (already in scaffold) with custom theme
- **React + Vite** (already scaffolded)
- **react-router-dom** for SPA routing
- **No heavy charting libraries** — use lightweight SVG/Canvas for charts (or lightweight lib like `recharts`)
- **Capacitor-ready** later — clean structure, no browser APIs that break in WebView

## Pages

### 1. Dashboard (Home)
- Current algorithm decision (mow now / wait + reason)
- Growth estimate (mm) with gauge/bar
- Rain delay status (safe to mow? hours remaining)
- Next predicted mow time
- Mower status (state, battery, last mow time)
- Weather summary (temp, rain, forecast)

### 2. Configuration
- All config parameters in form groups:
  - Grass & Growth (type, limits, model params)
  - Rain Delay (min delay, heavy rain delay, soil type, drying factors)
  - Time Constraints (min/max between mows, avg duration)
  - Algorithm Timing (run interval, cache TTL)
  - Weather Thresholds (max precip chance)
  - Mowing Windows (per day, time ranges)
  - Entity Groups (sensor IDs, mower entity, weather entity)
  - HA Input Helpers (enable/disable, entity IDs)
- Save/cancel with validation feedback

### 3. History
- Mow event calendar/timeline
- Growth over time chart
- Rain delay history chart
- Algorithm run log (filterable)

### 4. Algorithm Details
- Current growth model breakdown (GP factor, moisture factor)
- Rain delay calculation details
- Weather data visualization (historical + forecast)
- Decision tree visualization (why the algorithm made its decision)

## API Integration
- All data via existing REST endpoints
- Real-time updates via polling (no WebSocket needed)
- Config changes via PUT/PATCH to `/api/config`
